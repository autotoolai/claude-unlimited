# Claude Code 计划模式怎么用：四种权限模式的区别

> **一句话答案**：计划模式（Plan Mode）让 Claude 只读不写，先调查并给出方案，等你确认后才动手。它解决的是「我怎么知道它要干什么」，与「它能不能执行命令」（权限模式）是两件独立的事。三种进入方式：会话内按 Shift+Tab 循环、输入 /plan、启动时带 claude --permission-mode plan。

很多新手把计划模式当成「更安全的自动模式」，其实不是。它把「提方案」和「实施」分开：Claude 先读代码、查文件、理解任务，给出一份方案，停在那里等你批准。

## 四种权限模式的区别

**结论**：权限模式决定实施阶段哪些动作需要你批准，与是否在计划模式无关。

| 模式 | 行为 | 适合什么 |
|---|---|---|
| **plan** | 只读规划，等待批准 | 先看方案再动手 |
| **manual** | 默认；改文件、跑命令前逐条问你 | 日常开发，想控制每一步 |
| **acceptEdits** | 自动接受文件修改；命令仍要批准 | 改代码但不想每条都点 |
| **auto** | 自动批准所有动作（有后台安全检查） | 长时间无人值守任务，需信任环境 |

`manual` 是默认模式。`acceptEdits` 只管文件修改，不管命令执行。`auto` 最省事但风险最高，只在你确认环境安全、任务可回滚时用；它和跳过权限的差别见 [Claude Code 权限模式](/knowledge/claude-code-permission-modes)。

## 计划模式能做什么

**结论**：计划模式下 Claude 能读文件、列目录、跑只读命令（`git status`、`ls`、搜索），不会改文件、不会执行有副作用的命令。所以「只读」不等于「不能用工具」。

## 三种进入方式

1. **会话中按 `Shift+Tab`**：循环切换权限模式。从默认状态按第一下进 `acceptEdits`，第二下进 `plan`。
2. **输入 `/plan`**：直接进入计划模式，后面可以跟任务，例如 `/plan 修复登录跳转失败`。
3. **启动时带参数**：`claude --permission-mode plan`，只对这一次会话生效。

退出同样用 `Shift+Tab` 循环到你想要的模式。「按两下」是从默认状态算起的描述，如果已经在其它模式，看终端底部状态栏当前显示的名字。

## 让它给出一份能直接批准的计划

**结论**：一个好的计划要让你能一眼看出「改哪几个文件、为什么、怎么算做对」。

提问时带上这两样东西：

- **已知路径**：`@src/api/handler.ts` 直接引用文件，比让它自己搜更快、用更少 token；
- **验收标准**：「改完后 `npm run test -- handler` 通过，且不改动导出的函数签名」。

一个可用的任务描述长这样：

```text
修复用户注册后收不到邮件的问题。
相关文件：@src/auth/register.ts、@src/mail/send.ts
先给我方案，不要改文件。
验收：注册接口返回 200，且 send 被调用一次。
```

## 什么时候值得先规划

**结论**：任务范围需要确认、改动跨多个文件、或者你不确定它理解得对不对时，先规划。小改动、单文件、目标明确的任务直接做更快。

值得规划的场景：重构一个模块、给功能补测试、迁移配置、修一个你不熟悉的 bug。它会先把相关文件读一遍，列出「我打算改 A、B、C，原因是…」，你确认后再动手，避免改了一半才发现方向错了。

不值得规划的场景：改个错别字、加一行日志、单文件里一个明确的 bug。多一轮计划对话反而慢。

## 怎么审查它的计划

**结论**：看三件事：改动范围是否超出你的要求、有没有误读你的意图、验收标准是否覆盖了你真正在乎的行为。

发现问题就在对话里纠正：「第三步不用动数据库，改成读配置」。批准后再切回实施模式。批准计划只是表示认可方案，实施时用哪个权限模式仍然由你决定。

## 计划模式省 token 吗

**结论**：没有固定的节省比例，但能减少浪费。已知路径省掉的是搜索 token，验收标准省掉的是返工轮次。计划本身要读文件、生成方案，也消耗 token。

准确的表述是「减少不必要的搜索与修改轮次」，不是「计划模式更省」。更多降本的工程做法见[降低 Claude 用量的工程方法](/knowledge/reduce-token-usage-tips)。

## 让计划模式成为默认

在 `~/.claude/settings.json` 里设：

```json
{
  "permissions": {
    "defaultMode": "plan"
  }
}
```

只想某一次用启动参数即可。默认模式写在用户设置里，不写在项目的 `.claude/settings.json` 里。

## 计划模式与模型搭配

`/model` 里「用 Opus 规划、其它工作用 Sonnet」这类模型搭配（以 `/model` 实际列表为准），与计划权限模式不是一回事。一个是「用哪个模型想」，一个是「要不要先想再做」，两者可以独立组合。

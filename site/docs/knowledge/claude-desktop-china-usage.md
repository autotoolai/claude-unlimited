# Claude 桌面版在国内怎么用：注册、网络与登录

> 正式发布地址：[claude-unlimited.aiautotools.com/knowledge/claude-desktop-china-usage](https://claude-unlimited.aiautotools.com/knowledge/claude-desktop-china-usage) ｜ 源码与文档：[GitHub 仓库](https://github.com/autotoolai/claude-unlimited)

> **一句话答案**：官方支持地区清单里没有中国大陆，184 个支持地区中包含台湾、新加坡、日本、韩国，不含内地与港澳，所以「注册官方账号」这条路在国内走不通。但桌面版客户端本身可以正常下载安装，改用 API Key 加本地路由的方式配置之后，不登录官方账号也能正常使用对话和 Claude Code。

这个问题有两半，答案正好相反，所以先要分清楚。

一半是「能不能用官方账号」：不能。Anthropic 的产品与服务只对支持地区清单里的国家开放，清单里没有中国大陆，官方也明确写了未列出的地区属于不支持范围，人在不支持地区使用属于违规。

另一半是「能不能用桌面版这个客户端」：能。客户端是一个本地程序，装上之后它只是个壳，真正干活的模型调用可以走第三方兼容接口。把这一步拆开看，桌面版在国内是能用的，而且用的是完整功能，不是阉割版。

本文按这个顺序展开：先说清官方支持地区到底怎么规定的，再说清楚客户端和账号是两件事，然后给出国内用户实际可行的完整配置路径（每一步都有截图），最后收拢常见疑问。配置流程与[使用教程](/guide/desktop)同源，文章版更紧凑，看完这一篇就能装好。

## 官方支持地区清单是怎么规定的

**结论**：Anthropic 的支持地区清单目前列出 184 个国家和地区，中国大陆不在其中；台湾、新加坡、日本、韩国在清单里。清单没列的地区一律视为不支持。

官方在这条政策里明确了三层限制，不只是「你人在哪」这一条：

| 限制对象 | 官方口径 |
|---|---|
| 人 | 人身处不支持地区时使用，属于违规，不管账号注册在哪个国家 |
| 实体 | 注册地或总部在不支持地区的实体，其成员使用同样受限，哪怕人住在支持地区 |
| 股权 | 被不支持地区的人或实体直接或间接多数控股的实体，其用户与员工同样受限 |

这条政策覆盖的不只是网页版。官方原文写的是「our apps (such as Claude.ai, Claude Code, and Cowork), our API and developer platform」，也就是桌面客户端、Claude Code、Cowork、API 与开发者平台，全都在同一份清单约束下。

所以在国内，「注册一个官方账号然后登录桌面版」这个路径的问题是根本性的，不是某个开关没打开。清单位置是 Anthropic 官网的支持地区政策页，本文核对日期为 2026-10-26。

## 客户端和账号是两件事

**结论**：桌面版安装包是公开的本地程序，装完不登录也能打开界面；它与官方账号绑定的是「哪些功能要付费计划」，而不是「不登录就完全不能用」。

装客户端这一步没有地区门槛。官方安装文档里给出的系统要求是：

| 系统 | 要求 |
|---|---|
| Windows | Windows 10 或更高版本 |
| macOS | macOS 13（Ventura）或更高版本 |
| Linux | Ubuntu 22.04 LTS+ 或 Debian 12+，x64 或 arm64（测试版） |

装完之后「用你的账户登录以开始使用」是官方给的流程，但这只是默认路径。桌面版是 Electron 应用，真正的对话请求要发到服务端；服务端是谁、凭据是什么，完全由本机的配置决定，而不是由安装时登录的那个账号决定。

这一点也是为什么国内用户能做到「不用官方账号也能用」。把模型调用的出口换成一个兼容 Anthropic 协议的第三方网关，桌面版就变成一个普通的本地客户端。

要提醒一点：换出口不等于换地区政策。用第三方接口调用模型，和「以官方订阅账号身份使用 Claude 服务」是两回事，前者走的是 API 通道，后者受订阅条款与地区政策约束。自己在两者之间划清楚，别混着用。

## 国内实际可用的三条路径

**结论**：按「要不要官方账号」和「要不要写代码」两个维度分，国内用户实际有三条路可选。

| 路径 | 需要官方账号 | 需要终端 | 适合谁 |
|---|---|---|---|
| 第三方 API Key + 本地路由 | 否 | 只在配置阶段 | 想用完整桌面版功能的人 |
| 浏览器里直接用第三方接口 | 否 | 否 | 不想装客户端的人 |
| 官方订阅账号登录 | 是 | 否 | 人在支持地区的人 |

第一条是覆盖面最广的。装好一个配置管理工具，在里面新增一个「桌面版」类型的供应商，接入方式选直连，填上接口地址和 API Key，打开本地路由开关，启用并检测链路通过，桌面版就能用。下面的配置流程就写这条。

第二条更轻，把接口地址和 Key 填进任何支持 Anthropic 协议的工具里就能对话，缺点是拿不到桌面版独有的文件与代码能力。

第三条不适用于人在中国大陆的读者，但对在支持地区的朋友是标准路径，也是唯一能解锁全部官方功能的路径。

对国内用户来说，第一条和第二条在模型能力上没有差别，差别只在于界面形态。桌面版额外提供的是本地文件操作、代码执行、多会话并排这些能力。

## 配置桌面版：从换 Key 到正常对话

**结论**：整条链路是七步 —— 装 CC Switch、换 API Key、新增桌面版供应商、填地址与 Key、打开路由、启用并检测、装客户端并对话。每一步都有对应的界面截图，跟着走就能配完。

下面每小节一步，界面图是真实配置时的样子，标注的位置就是要点的地方。

### 第一步：装 CC Switch

CC Switch 是一个专门管 API 配置的小工具，装好之后所有供应商配置、路由开关都在里面管。软件很小，不需要注册账号，一路默认安装即可。

<GuideShot src="guide_ccswitch_site.png" caption="CC Switch 官网首页，Windows 与 macOS 版都在这里" />

### 第二步：把卡密换成 API Key

卡密在发货信息里，拿到后到管理后台换成一把 `sk-` 开头的 API Key，后面全程只用它。

功能说明见 [rsxermu666.cn 管理后台](/console)。实际兑换请打开 [rsxermu666.cn](https://rsxermu666.cn/)，在「我的面板」或「提取 Key」页面粘贴激活码，提交激活后复制拿到的 Key。

<GuideShot src="guide_site.png" caption="管理后台首页，粘贴卡密的输入框在这里" />

激活码、API Key、用量记录都存在后台里，换设备、换浏览器都不影响。忘了就回后台用同一把激活码再看。

### 第三步：新增桌面版供应商

桌面版在 CC Switch 里是一个单独的供应商条目，要自己新建，不能用一键导入。先切到带显示器角标的那个应用图标，列表里出现「Claude Desktop Official」就对了。

<GuideShot src="guide_desktop_provider_picker.webp" caption="CC Switch 供应商列表里的 Claude Desktop Official 条目" zoom />

点右上角橙色「+」，在「添加新供应商」页的预设列表里选「自定义配置」。

<GuideShot src="guide_desktop_provider_preset.webp" caption="「添加新供应商」弹窗，预设列表里选「自定义配置」" zoom />

预设供应商里带「Claude Desktop」字样的那些都不是本卡，填了也不通。

### 第四步：填接口地址与 API Key

这一步有三个值要填，填错的表现是连不上或报鉴权错误：

| 字段 | 填什么 |
|---|---|
| 请求地址 | `https://rsxermu666.cn` |
| API Key | 上一步换来的 `sk-` 开头那把 |
| 接入方式 | 直连 |

<GuideShot src="guide_desktop_provider_form.webp" caption="编辑供应商：请求地址、API Key 与接入方式「直连」" zoom />

两个容易填错的地方：地址后面不要自己加 `/v1` 或 `/chat/completions`，填了会 404；接入方式选「模型映射」也能连，但要多配一层模型映射，直接选「直连」最省事。

主域名打不开或很慢时，换备用域名 `bxcv.store`，API Key 不用换。

### 第五步：打开路由开关

桌面版必须走本地路由转发，请求才会被送到网关 —— 这一步不做，前面配的全都白配。

进 CC Switch 的「设置 → 路由」，打开「路由总开关」，再在「路由启用」里打开「Claude」。

<GuideShot src="guide_ccswitch_route_settings.webp" caption="CC Switch 设置里的「路由」页：路由总开关与各应用开关" zoom />

路由服务地址默认是本机的 `127.0.0.1:15721`，不用改。改完地址或端口要重启路由服务才生效。

回到 CC Switch 主界面，这条配置名字旁边有蓝色小标「需要路由」，看到这个标记才说明请求会走本地转发。

<GuideShot src="guide_ccswitch_provider_route.webp" caption="CC Switch 供应商列表里标着「需要路由」的两条配置" zoom />

### 第六步：启用并检测链路

回到主界面点「启用」，再点「检测链路」，弹出「连通正常」即可。不启用的话配置不会写进客户端。

<GuideShot src="guide_desktop_link_ok.webp" caption="检测链路显示 claude 连通正常" zoom />

### 第七步：装客户端并开始对话

到 Claude 官网的下载页选自己的系统，下载后双击安装。

<GuideShot src="guide_desktop_download.webp" caption="Claude 官网的桌面版下载页" />

装完打开桌面版，随便问一句（比如「你是什么模型」），能正常回答、模型对得上，就说明整条链路配成了。

<GuideShot src="guide_desktop_cowork.webp" caption="桌面版里正常对话，模型为 Fable 5.1" zoom />

官网页面在国内有时打不开，可以用镜像地址：[l1i1.github.io/ClaudeDesktop-Installer](https://l1i1.github.io/ClaudeDesktop-Installer/)；镜像是第三方文件，装之前自己判断要不要用。只装客户端即可，API 继续用前面配好的 CC Switch。

配置过程中的详细步骤与各客户端对照，看[Claude 桌面版教程](/guide/desktop)；换到终端用的话看[Claude Code CLI 教程](/guide/cli)。

## 国内用桌面版要额外准备什么

**结论**：客户端本身没有额外的地区检测，重点是三件事：下载源、账号登录入口、以及哪些功能不依赖官方账号。

下载源方面，官方下载页是首选；官网页面在部分网络环境下打开不稳定或很慢，这属于可达性问题，不是被封。

账号登录入口要清楚它的作用边界。桌面版登录后得到的是官方订阅的身份，这个身份对应官方计划与官方渠道。走第三方接口时，你并不需要这个身份，配置完成后直接进入对话即可。官方文档给出的功能准入表是这样的：

| 功能 | 免费 | Pro | Max | 团队 | 企业 |
|---|---|---|---|---|---|
| 对话 | 有 | 有 | 有 | 有 | 有 |
| Claude Code | 无 | 有 | 有 | 有 | 有 |
| Claude Cowork | 无 | 有 | 有 | 有 | 有 |

这张表说的是「用官方订阅身份时每个计划能开哪些功能」。它解释了为什么有些人在桌面版里看不到某些入口：不是地区问题，是计划问题。

不依赖官方账号的功能是客户端本地的那部分：本地文件读写、项目目录管理、界面本身。这些走第三方接口一样能用。

如果想了解客户端在配置完成之后具体能做什么、桌面版和终端里的 Claude Code 有什么区别，看[Claude Code 与 Codex CLI 怎么选](/knowledge/claude-code-vs-codex)和[Claude Code 教程：第一次会话之后怎么用](/knowledge/claude-code-tutorial)。

## 什么情况下这条路会失效

**结论**：三类情况会让桌面版用不起来，都跟配置和文件有关，跟地区无关。

第一类是本地功能没开启。Windows 上首次使用桌面版的文件与代码能力，可能弹出提示要求启用虚拟机平台。这是系统的可选功能没开，在系统设置里勾选后重启即可，跟接口配置无关。

<GuideShot src="guide_desktop_vm_error.webp" caption="提示需要 Virtual Machine Platform 的报错弹窗" zoom />

打开 Windows 搜索框，输入「启用或关闭 Windows 功能」打开它。

<GuideShot src="guide_desktop_vm_search.webp" caption="Windows 搜索「启用或关闭 Windows 功能」" zoom />

在列表里勾选「虚拟机平台」和「适用于 Linux 的 Windows 子系统」，确定后重启电脑。两个都勾上，桌面版的代码与文件功能才完整可用。注意「Windows 虚拟机监控程序平台」不是同一个东西，别勾错。

<GuideShot src="guide_desktop_vm_features.webp" caption="Windows 功能列表里勾选「虚拟机平台」与「适用于 Linux 的 Windows 子系统」" zoom />

第二类是配置没有真正生效。常见表现是界面能打开但发不出请求，或者报鉴权错误。排查顺序是先确认本地路由开关是打开的，再确认供应商条目处于启用状态，然后完全退出客户端（不是最小化到托盘）再重开。终端侧的鉴权类问题可以看[Claude Code 报错 401 / 403 怎么解决](/knowledge/claude-code-401-403)。

第三类是网络链路本身不通。桌面版能启动但请求超时，往下查就是 DNS、代理与企业中间人证书的问题，方法在[Claude Code 连接中断、等待 API 响应怎么处理](/knowledge/claude-code-connection-lost)里，本文不重复。

还有一类风险不在这三类里，但值得提前知道：把账号登录当成唯一入口的人，最后往往卡在「注册不了」这一步。桌面版真正的价值在于它是个本地客户端，谁提供模型是另一件事。把这两层拆开，绕开的是路径选择，不是绕过任何技术限制。

# Claude Code 报 429 限流怎么办

> **一句话答案**：429 表示你在某一项每分钟上限上超了：请求数、token 数、或者并发在途请求数。Claude Code 会按 retry-after 等待并重试，多数几秒内自愈；持续超限就按顺序处理：减少并行子代理、`/compact` 压缩上下文、`/model` 换档、把后台工作挪到便宜档，最后才是申请提额。

## 429 是什么意思

**结论**：HTTP 429 是「这一分钟你用得太多了」。它与套餐额度无关，是速率限制，过一会儿自己恢复。

Claude Code 遇到它会打印重试行并按退避等待：

```text
API Error: 429 rate_limit_error · Retrying in 2s · attempt 2/10
```

## 三个上限

**结论**：三个上限同时生效，都按模型分别计算。

| 上限 | 含义 | 谁容易撞上 |
|---|---|---|
| 每分钟请求数 | RPM | 高频短调用、批量任务 |
| 每分钟 token 数 | TPM，输入与输出都算 | 长上下文会话，每轮都重发历史 |
| 并发在途请求数 | 同时进行的流式请求 | 子代理并行、批量扇出 |

用无限额度时不会改变这三个机制，它们是服务的稳定性约束，不是计费。数值见[常见问题](/faq)。

## 为什么 Agent 比聊天客户端更容易撞上

**结论**：三个原因叠加。

1. **每轮都流式输出**：整个响应过程都占住一个并发位，聊天客户端发完就等，Agent 一直在生成；
2. **子代理并行**：十个子代理就是十个同时进行的流，每个都算独立请求；
3. **每轮重发完整会话**：token/分钟随会话长度攀升，聊天的短消息不会这样。

## 六步处理，按有效顺序

**结论**：从上到下，多数情况在前三步就解决了。

1. **让它重试**。429 大多在 10 次内置重试内自愈，不要一看到就中断。
2. **减少并行**。少开子代理，重任务排队而不是扇出。
3. **`/compact`**。上下文越小，每轮 token 越少，直接压住 TPM。
4. **`/model` 换档**。上限按模型计算，换一个档位就是换一组额度。
5. **后台工作挪到便宜档**。主循环留给主力档。
6. **申请提额**。带上你的账户与工作负载联系客服；新账户的并发从保守值起步，可以按需调整。

脚本里配合限制轮次：

```bash
claude -p "..." --max-turns 20
```

## 和 529 的区别

**结论**：429 是你超了自己的速率；529 是模型整体容量不足，所有人都受影响。见到 `overloaded` 字样就是 529，处理办法见 [529 怎么处理](/knowledge/claude-code-529-overloaded)。

# 用代码做视频：四个开源技能怎么选

> **一句话答案**：代码做视频不是让模型生成像素，而是让它写一段程序，程序在每一帧算出一个画面，再把帧拼成 MP4。所以产物可复现、可编辑、文字永远清晰；代价是素材要你自己准备，第一次配环境要花点时间。四个开源技能按分工选：宣传片走 video-shotcraft，科普讲解走 anything2explainer，口播教程走 video-talkcraft，想避开 Remotion 授权走 claude-motion-design。

如果你只需要"让画面动起来"，直接去 [Claude Code 教程：从零跑通第一条 MP4](/knowledge/claude-code-make-video)，那篇只讲 Remotion 这一条路。本文讲的是路已经跑通之后的事：四个技能各自擅长什么、开拍前要准备什么、哪些坑会让你白渲一遍。

## 代码做视频和文生视频差在哪

**结论**：两条完全不同的路线。文生视频是模型逐帧生成像素，适合实拍质感与人物表演；代码做视频是每一帧由程序算出来，适合文字多、规则明确的画面。

| 做法 | 谁在画 | 适合 | 不适合 |
|---|---|---|---|
| 文生视频 | 模型生成像素 | 实拍质感、人物表演 | 文字多的画面、长镜头 |
| 代码做视频 | 你和 Claude 写的代码 | 字幕条、数据动画、logo 演绎、代码演示、产品宣传片、科普讲解 | 照片级真实人物 |

最关键的差别是**可复现**。同一份代码渲染一百次结果完全一样；你改一行文案重渲，只有受影响的部分变。生成式视频做不到这点，同样输入两次可能给出不同结果。

## 四个技能的场景分工

**结论**：没有哪个技能是万能的。选型只看一件事：你要做的片子里，信息是怎么组织的。

| 场景 | 推荐技能 | 一句话理由 |
|---|---|---|
| 产品宣传片、发布片 | video-shotcraft | 一整套镜头配方卡，每张写明何时用、时序、缓动与已知坑，直接对着挑 |
| 科普讲解（黑板风 MG） | anything2explainer | 主题进、解说视频出，字幕、章节进度条、进度 HUD 全套现成，质检判据都成文了 |
| 口播教程（配音驱动） | video-talkcraft | 配音是输入不是产出，字级时间戳锁住画面动效，适合"讲步骤" |
| 纯代码动效、不用 Remotion | claude-motion-design | `seek(t)` 纯函数引擎加 Playwright 逐帧渲染，不依赖 Remotion 授权 |

前三个都是 Remotion（React）路线，第四个是 HTML 加 Playwright 路线。这一条本身就是选型理由：想避开 Remotion 的许可与版本约束，第四个是现成出路。

## 开拍前要准备什么

**结论**：四个技能里有三个的产物质量，直接取决于你给的素材质量。素材不到位，再好的技能也救不回来。

| 素材 | 什么时候要 | 怎么拿 |
|---|---|---|
| 真实页面截图 | 宣传片、界面演示 | 无头浏览器 1920 视口截图，2 倍像素密度 |
| 终端录屏 | 讲操作的教程 | 跑一遍真实命令再录，不要摆拍 |
| 口播稿 | 科普、教程 | 先写稿再配音，不要边配边改稿 |
| 配音文件 | 口播类必备 | 见下方「中文配音」 |
| 品牌 token | 全部 | 从你自己产品的 CSS 变量里抄颜色和字体 |

**配音是最容易被低估的一项。** 实测下来，四个技能里有三个把配音当成硬约束：没有时间戳就不出片，因为字幕和动效都要靠它对齐。

### 中文配音：两条路线

**结论**：按你能不能连外网选，两条都可行。

| 路线 | 音色 | 优点 | 前提 |
|---|---|---|---|
| Kokoro-82M-v1.1-zh（本地） | 四个中文音色 | 免费、可商用、不联网、模型只有 82M | `pip install kokoro misaki[zh] soundfile`，中文音色要设 `lang_code='z'` |
| edge-tts（云端） | 十几个中文音色 | 音质自然，有词级边界，字幕节拍最准 | 需要能连 `speech.platform.bing.com`；连不上就握手 403 |

很多人 edge-tts 一装上就发现连不上。这不是配置问题，是网络问题。测试机直连被拒，系统代理端口也没在跑。机器同样情况就直接上 Kokoro。代价是 Kokoro 没有词边界，只能逐块合成，块起始帧仍然精确，但块界断句略生硬。

术语验读是必做项：MCP 念"M C P"还是别的、模型 ID 怎么读、`.json` 念不念"点 json"，都得单独试听定，不能想当然。

### 混音规范

| 项 | 数值 |
|---|---|
| 人声整体响度 | -14 LUFS |
| 音乐 | 压到 -18 LUFS 以下给人声让位 |
| 峰值 | 不超过 -1 dBTS |

工具就一条 ffmpeg：

```bash
# 这行把整体响度归到 -14 LUFS、峰值限制在 -1.5 dBTP
ffmpeg -af loudnorm=I=-14:TP=-1.5:LRA=11 -i in.mp4 out.mp4
```

开拍前要准备：官网首页 2 倍截图、档位名称与价格的真实文案、官网 SVG logo。

### 2. 上下文窗口与提示缓存

用了什么：黑底白线稿加紫点缀的固定视觉体系，本地模型配音，逐块对齐字幕，底部章节进度条。两个主题（上下文窗口、提示缓存）并进一支，各占一章。

### 3. MCP 是什么

<VideoPlayer src="v4_mcp.mp4" caption="36.0 秒 · 1920×1080 · 30fps" />

用了什么：五镜结构（终端 → 装手脚 → 能干什么 → 怎么装 → 装完什么样），句级时间戳锁动效，深空蓝主题。

开拍前要准备：配音成品与时间戳 JSON、脱敏后的配置示例、每镜的语义标注（这句在做什么）。

### 4. 一条视频是怎么算出来的

<VideoPlayer src="v6_seek_t.mp4" caption="41.0 秒 · 1920×1080 · 30fps" />

这条本身就是在讲这门技术。第一版用 claude-motion-design 的 `seek(t)` 引擎做，四支镜头全是并列的示意图，看不出因果关系，而且零解说零字幕，观众没有进入点。第三轮推倒重做，换成 Remotion，五镜改成一条完整因果链：写脚本 → 脚本切成时间轴 → 每一秒交给函数算一帧 → 一帧帧接成视频 → 改一句重渲。

开拍前要准备：先定稿解说词（它是唯一真源，画面按句切）、每个元素锚到具体的字、标题前 5 帧给完成态构图。

## 怎么按自己的场景选

**结论**：三步就能定下来。

1. **数一下片子里要出现几段解说**。有配音、需要字级对齐就走 video-talkcraft。只有字幕或纯画面就跳过这步。
2. **看画面是抽象示意图还是真实界面**。真实界面（你的产品、你的终端）走 video-shotcraft，它整套方法论围绕"先起服务再截图"；抽象示意图走 anything2explainer 或 talkcraft，它们更适合画概念。
3. **看你要不要避开 Remotion**。要就 claude-motion-design，它自带完整引擎。不要就前三个随便挑，都成熟。

只有一种情况建议自己写：**片子要同时有真实界面和抽象示意**，比如先演示一遍真实产品，再用抽象图解释原理。这时用 video-shotcraft 的方法论但自己搭工程，比硬套任何一个技能都顺。

## 你只需要给什么

**结论**：五个样片做了两轮，最容易走偏的就是这件事——把技能该做的设计当成需求写进去。用户给方向，技能做设计。

| 该给（五样） | 不该给 |
|---|---|
| 主题或产品入口 | 分镜表、镜头时长 |
| 时长（3 分钟以内单章，3 到 5 分钟 3 到 4 章） | 每个元素的出现帧号 |
| 要不要解说（要或不要） | 字幕位置、字号、安全区 |
| 配音偏好（没有就用默认） | 逐元素的时间戳锚点 |
| 素材路径（截图、录屏、产品页面） | 运镜曲线、缓动参数、镜头配方卡编号 |

**为什么不该给**：这些是技能的内部实现。三个 Remotion 技能各自的字幕锚点、故障序列、镜头卡都是技能自己按时间轴和语义段落推导的。你手填的版本会和技能的自动设计冲突：第一轮手填字幕位置，结果和字幕组件的默认位置打架。

**正确的协作方式**：需求只给方向，让技能先出 30 秒样片；样片确认后再提具体修改意见，而不是在需求阶段就把实现细节写死。

## 机器闸：人眼审片会漏，断言不会

第一轮人工审帧，认为两支片子通过。实际上那两支的场景根本没挂载成片，上部区域像素标准差是 **0.00**，整片只有字幕。原因是调用 `sceneFrameRanges()` 时少传了参数，返回 `undefined`，五个场景全被 `if (!r) return null` 拦掉。

**这类问题靠人眼和静帧都看不出来。** 当时抽的是静帧，静帧里场景是正常的（那是从 Remotion 直接渲的单帧），只有合成后的视频才暴露。

第二轮加的七道闸在出片后一条命令跑完，退出码非 0 即不出片：

```bash
python scripts/gates/run_all.py outputs/your_video.mp4
# a2e 风格的片子再加一条静止上限
python scripts/gates/run_all.py outputs/explainer.mp4 --motion-std=3.0
```

七道闸分别是：场景挂载、动画密度、布局侵占、解说一致性、响度、首帧完整度、音轨非空。其中最该先上的是第一道，它拦住的是最贵的一类错误（整片渲染白费）。

## 三轮迭代实录

同一批样片迭代了三轮，每轮都有明确的输入、明确的发现、明确的改动。下面按真实经过写，不美化。

### 第一轮：给了什么，发现了什么

**输入**：一个主题、五句解说词、一张官网截图。

**结果**：片子都渲染出来了，但两支有硬伤——成片是纯色底加字幕（场景根本没挂载），宣传片没有解说，而抽静帧审片却认为"画面正确"。

**为什么没发现**：静帧是从 Remotion 直接渲的单帧，场景是正常的，只有合成后的视频才暴露。另一支看的时候工作目录漂移了，把上一支的帧当这支的看了。

### 第二轮：补齐流程，加机器闸

**输入**：同上的内容，加上语义标注、镜头手册与 shots.json，以及一套七道机器闸。

**为什么这次不一样**：科普与口播两个技能都要求先产出这几个中间文件，第一轮跳过了。而且两个技能都自带质检脚本（口播技能的 `preflight.py` 会在渲染前拦语义覆盖，`freeze_probe.py` 会预判静止段），一次都没跑。

| 指标 | 第一轮 | 第二轮 |
|---|---|---|
| 两支片子上部像素标准差 | 0.00（场景没挂载） | 92.18 / 92.58 |
| 两支最长静止 | 23.0s / 27.25s（全片） | 0.00s |
| 宣传片有无解说 | 无 | 已补 28.8 秒 |
| 科普片首帧 | 纯黑 | 正常 |

**但第二轮自己也有盲区**：七道闸能验"场景挂没挂""动没动""字有没有压字幕"，验不了"排版挤不挤得下"。宣传片的卡片文字实际超出 122px，七道闸全过，肉眼能看出来，却漏了。

### 第三轮：加排版守卫，推倒重做一支

**输入**：同上的内容，加上排版预算守卫。

1. **宣传片卡片**：卖点文案从 19 到 31 字缩到 8 到 10 字，卡片高度 400 改 460，价格字号 72 改 66。排版守卫实测从"超 122.3px"变成"余量 46.1px"。
2. **宣传片尾部**：修掉一个此前完全没发现的问题——CTA 的入场帧是 214，而 Sequence 只有 215 帧，永远等不到；加上总时长多出 100 帧，尾部 3.5 秒实测是纯白（标准差 0.000）。改成收尾层按绝对帧常驻。
3. **原理片推倒重做**：从 `seek(t)` 引擎换成 Remotion，五镜改成一条完整因果链。
4. **两支加长**：解说从 5 句加到 10 句，字级锚点从每镜 0 到 2 处补到 2 到 3 处。

### 机器闸是怎么一步步长出来的

七道闸不是一开始设计好的，是被每一轮的问题逼出来的：

| 闸 | 为什么会加它 |
|---|---|
| `g0_scene_mounted` | 第一轮场景没挂载成片，人眼和静帧都没看出来 |
| `g3_vo` | 第一轮宣传片干脆没有解说 |
| `g5_first_frame` | 第二轮科普片首帧是全黑，而平台抓第一帧当封面 |
| `g3_layout_fit` | 第二轮宣传片卡片文字溢出，七道闸全过却肉眼可见 |

**这条才是本文真正想教的方法**：不是记住七个阈值，而是每次肉眼发现一个质量问题，就把它变成一条断言。第三轮加排版守卫时还踩了一个坑——守卫里的文案引用解析失败被 `or []` 静默吞掉，导致卖点完全没算进去，守卫报"PASS 余量 110px"，而手算是"超 122px"。漏算还报 PASS 是最坏的形态，比报错危险得多。

## 踩坑清单

以下每一条都是真实撞到的，照着避。

| 坑 | 现象 | 解法 |
|---|---|---|
| TypeScript 版本 | `npm i -D typescript` 装到 TS 7，Remotion 报 `Cannot read properties of undefined (reading 'readFile')` | 钉 `typescript@5.9.3` |
| 图片引用 | `<Img src="home.png">` 404 | 必须 `staticFile('assets/home.png')` |
| 文件后缀 | 镜头组件写成 `.ts`，TS 报一堆 `'>' expected` | 镜头文件一律 `.tsx` |
| edge-tts 连不上 | WebSocket 握手 403 | 开代理，或改用 Kokoro |
| motion-design 页面卡住 | `window.ready` 永不置位 | 引擎默认预载 11 个 logo 与 Geist 字体，缺了就 404 阻塞 `fonts.ready`；删掉预载改系统字体 |
| 渲染脚本硬编码 | 渲染脚本里的 URL、时长、输出名是原片常量 | 逐个改 |
| 首帧空白 | 前几帧淡入，第一帧被平台抓去当封面时是一片底色 | 前 5 帧直接给完成态构图 |

最后一条值得单独强调：**第一帧必须是完整画面**。社交平台会直接抓视频第一帧当缩略图，第一帧是空白底色或半截入场动画，热度和点击都会打折。

## 质检怎么做

**结论**：自动检查能证明结构一致，但视觉和听感必须自己看，两件事都要做。

自动检查用 ffmpeg 就够：

```bash
# 首帧是不是完整画面（唯一灰度值越多，内容越完整）
ffprobe -v error -select_streams v -show_frames -show_entries frame=pkt_pts_time \
  -of csv outputs/your_video.mp4 | head -1

# 整体响度
ffmpeg -hide_banner -i your.mp4 -af "loudnorm=I=-14:TP=-1:LRA=11:print_format=json" -f null -
```

人工审片看三样：抽 1fps 联系表逐帧过一遍找穿帮、每个转场前后各看一帧确认没有半帧断、完整试听一遍确认音乐没盖人声。自动检查全绿但没人看过的情况，要在结果文档里如实标注。
